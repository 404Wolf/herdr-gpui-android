## Tab names: #54

In a **project strip**, the actual labelled PM's tab is always `lead`, overriding any name label. Other tabs use the terminal's nonempty `labels.name`, then the first useful task candidate (title, physical tab name, core name / loose-terminal label), then `window N`. N is the position in the full strip, starting with lead at 1, not the physical tab index or terminal id. Generic role/harness/shell names, numbers, and raw local or machine-qualified terminal addresses do not count as tasks. An explicitly supplied name label is an override. The deacon strip retains the desktop's separate role-naming behavior; the project-strip rule is not a blanket removal of diagnostic terminal ids throughout Home or the sidebar. Source: #54 `stripLabel`, lines 687–702 at its audited head.

## Repository headers: #53

For a project with a **labelled PM**, choose the header in this order:

1. Nonempty `repo=` label on the PM, else the first project agent carrying one. A URL-valued label uses the same remote-name normalizer.
2. The PM's own resolved Git repository.
3. The repo component of the PM's standard `~/.herdr/worktrees/<repo>/...` path when Git is gone.
4. The repo most project agents work in, then the project's own spaces' checkouts if no agent repo resolves.
5. One **Other** header, after all repository headers.

The majority is **one vote per agent with a resolved repo**, not one per distinct checkout top: two agents in one checkout cast two votes. Ties prefer a repo with a main-checkout agent, then the first repo encountered in the existing stable order. Space metadata is a fallback, not extra votes. This differs from the existing ahead-count subtotal, which deliberately deduplicates checkout tops. Source: #53 `fleet`, lines 589–598; `mostUsedRepo`, lines 708–716.

Name a resolved repo from `origin`'s URL, else the first remote; with no usable remote, use its own repository folder name. The normalizer trims whitespace, removes query/fragment, trailing slashes, a case-insensitive `.git` suffix and trailing slashes again, then takes the last slash/colon/backslash-separated component; empty/dot-only names are absent. Examples: `ssh://gitea@host:2222/org/monopoly.git`, `git@github.com:o/monopoly`, `https://host/o/monopoly/`, and `/srv/git/monopoly.git` all name `monopoly`. A checkout folder `pricing` with that remote belongs under `monopoly`. Source: #53 `remoteName`, lines 249–257; remote read/parse at :241 and :1675.

A labelled PM without a repo must not create a header named after its cwd or project. **Other** is open by default, folds on tap, remembers its fold and follows repos in navigation order. Its identity must be distinct from a real repository named `Other`. Projects without a labelled PM retain the existing repo / known repo-name / Outside git rules, including idle placement. Same display names still share a header while separate canonical repos retain their separate unopened-worktree catalogs.
