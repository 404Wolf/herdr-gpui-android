## Implementation and verification

The Java change shares `FleetTree.projectTarget` and `unopenedLabel`, reuses the existing worker threads / `space.open` endpoint, preserves exact terminal routing, adds in-flight deduplication to rail worktree opens, and fences late successful replies against both the active session and the latest navigation intent. It also wires Home's Fleet machine rows and gives chips, tabs and independent fold chevrons pressed feedback.

`RailClicksTest` was written in the existing JUnit 4 style: PM/worker selection, no-PM nested children, no fabricated target for an empty project, full/truncated catalog labels and pagination, current-terminal/path matching, plus source guards for actual Home/rail listeners, shell endpoint use, duplicate/late-result guards and pressed drawables. Source guards do not prove Android input delivery or native rendering.

Validation is limited to static source/diff review and `git diff --check`. Run the JUnit suite and perform phone QA once a build slot is available: narrow and wide Home, no-PM parent and child taps, catalog-only folds, busy/offline catalog taps, duplicate opens, switching hosts before replies, pressed states and keyboard focus. No build/test/native result is claimed here.

## Follow-up item 35: repository headers

The PM added item 35 after the audit: restore collapsible repo headers and project counts while keeping the PMs-only layout. Home and the rail now consume the same `FleetTree.PmTree.repos` projection. Each repo header and its chevron folds that repo's PMs with pressed feedback; PMs keep their own worker/catalog folds and main tap actions. Repo headings start expanded. Group state is scoped to the computer; changing focus can reveal the new selection's repo, while a manual fold survives repeated polls and startup does not force anything open.

Grouping matches the desktop rule: the PM's own git repo first; if unavailable, the repo this project's other agents/spaces resolve to; then the conventional `~/.herdr/worktrees/<repo>/<checkout>` name; then the project label. Canonical common git paths distinguish repositories sharing a basename. Repo counts count projects, including a missing-PM project that still has labelled workers; Deacons, helpers and Other terminals do not inflate them. Blocked work also marks the repo header.

`FleetReposTest` was written for common-repo grouping across arbitrary checkouts, name order and project counts, fallback order, worker-repo backfill versus known PM git, duplicate basenames, no-PM projects, excluded Deacons/helpers/shells, default fold policy, per-machine focus/reveal isolation and shared Home/rail projection wiring. Existing sidebar tests were updated for repo headings. These tests also remain **unrun** under the slot restriction.

## Async navigation and no-PM target corrections

Home's async worktree, Deacon and terminal-focus opens share a navigation epoch and session-handle completion gate. Picking another computer, opening another terminal, browsing navigation controls or leaving Home invalidates older navigation results even if the original computer remains connected. Each stage of an accepted open carries the same intent rather than creating a new one on completion.

A no-PM tap prefers the first actual agent/worker in display preorder, including one beneath a bare shell parent. A shell is used only when no agent remains. `HomeNavigationTest` covers delayed replies after selecting a host with no Deacon, intervening same-host terminal choices, both open stages and session replacement. `RailClicksTest` adds shell-before-worker and shell-parent/worker-child fixtures and the shell-only fallback. These tests are written, not run; JUnit + emulator QA pending the heavy slot.
